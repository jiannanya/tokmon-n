## 一、微内核与生命周期

### 1. Nyxia — 微内核

Nyxia 是整个 Tokmon 系统的**时空基座**，负责管理一切底层资源与生命周期。

**核心职责：**

- **Context 继承树管理**：维护系统中所有执行上下文的层级关系，形成一棵可追溯的继承树，每个子 Context 继承父 Context 的配置、变量与约束。
- **Fiber 实例管理**：管理轻量级执行纤程（Fiber）的创建、调度与销毁，支持高并发场景下的细粒度任务切换。
- **可逆 Effect 记录**：记录系统中所有可逆操作（Effect），支持回滚与重放，为确定性执行提供底层保障。
- **时空组合不变量**：维护系统运行时的时空一致性约束，确保跨时间、跨空间的操作组合不会破坏系统的不变量（Invariants）。

> Nyxia 不直接处理业务逻辑，而是为上层所有模块提供**可追溯、可回放、可组合**的执行基底。

---

### 2. Ignis — 插件加载器

Ignis 是系统的**点火装置**——在 Nyxia 的暮色中点燃第一簇火焰，唤醒整个生态。

**核心职责：**

- **Manifest 校验**：解析并校验插件的声明清单（Manifest），确保其格式、依赖、权限声明完整且合法。
- **动态链接（C ABI / dlopen）**：支持运行时动态加载编译为 C ABI 的插件库，通过 `dlopen`/`dlsym` 等机制实现热插拔。
- **HMR（Hot Module Replacement）**：支持插件模块的热替换，无需重启系统即可更新插件逻辑。
- **DesiredComposition 协调**：根据系统当前状态与目标组合（Desired Composition），自动协调插件的加载、卸载与版本切换。

> Ignis 让 Tokmon 成为一个**可生长的系统**——插件即插即用，能力随需而变。

## 二、总线与生态互联

### 3. Lemon — 通信总线

Lemon 是 Tokmon 内部**所有模块间通信的枢纽**，负责进程内的信号交换与事件分发。

**核心职责：**

- **类型安全的 Signal**：基于 Axon 框架提供类型安全的消息信号（Signal）系统，编译期即可检查消息格式的正确性。
- **Typed Connection**：建立模块间的类型化连接（Typed Connection），确保通信双方的消息契约一致。
- **事件分发**：负责将信号/事件路由到正确的订阅者，支持单播、多播与广播模式。

> Lemon 的名字取自“柠檬”——跳跃的酸味象征信号在总线上的明快传递。

---

### 4. Iris — 协议桥接层

Iris 是 Tokmon 的**跨界使者**，负责连通 Tokmon 内部世界与外部异构生态。

**核心职责：**

- **MCP 客户端/服务端通信**：实现 Model Context Protocol（MCP）的客户端与服务端通信，让 Tokmon 能与支持 MCP 的外部工具和智能体互联。
- **LSP 代码智能协议**：集成 Language Server Protocol（LSP），为 Tokmon 提供代码补全、定义跳转、诊断等语言智能能力。
- **Node/Python Worker IPC 桥**：建立与 Node.js、Python 等外部工作进程的 IPC 通信桥接，让 Tokmon 能调用异构语言生态的能力。

> Iris 是彩虹女神，跨越神人两界——正如协议桥接层跨越 Tokmon 与外部世界。

## 三、推演、调度与流程

### 5. Rhea — 模型网关层

Rhea 是 Tokmon 的**智能涌流之源**，统一接入和管理各类大模型能力。

**核心职责：**

- **多厂商大模型适配**：统一接入 Anthropic、OpenAI、Deepseek、Gemini 等多厂商的大模型 API，屏蔽厂商间的接口差异。
- **流式 Reasoning/Token 解析**：支持流式（Streaming）推理响应，实时解析 Token 流并转发给上层模块。
- **退避重试与 Provider Broker**：实现智能退避重试策略，并在多个模型提供商之间做负载均衡与故障切换（Failover）。

> Rhea 是众神之母的乳水，奔涌不息——正如模型网关层持续输出智能 Token 流。

---

### 6. Janus — 调度层

Janus 是 Tokmon 的**双面门神**——回望过去的状态，凝视未来的任务，裁定每一道任务的宿命。

**核心职责：**

- **Agent Direct Loop 驱动**：驱动智能体（Agent）的主循环（Direct Loop），负责 Agent 的推理-行动-观察闭环。
- **Turn/Step 惯性状态机**：管理 Agent 的每一轮（Turn）和每一步（Step）的状态转换，确保执行流程具有“惯性”——即状态在步骤间自然延续。
- **单 Agent 生命周期控制**：管理单个 Agent 从创建、运行到销毁的完整生命周期。

> Janus 的两张面孔——一张看向 Nota 记录的过去，一张看向未来待执行的任务。

---

### 7. Clotho — 确定性流程

Clotho 是 Tokmon 的**因果纺织者**，负责确定性工作流的编排与执行。

**核心职责：**

- **确定性 DAG 工作流引擎**：基于有向无环图（DAG）构建确定性工作流，每一步的执行顺序和条件都明确定义。
- **多阶段批处理流水线**：支持将复杂任务拆解为多个阶段（Stage），以流水线方式批量处理。
- **条件分支与混合编排**：支持工作流中的条件分支（If/Else）、并行执行与混合编排，兼顾确定性与灵活性。

> Clotho 是命运三女神中的纺线者——她纺织的每一根线都决定了工作流的走向。

---

### 8. Aya — 多智能体层

Aya 是 Tokmon 的**灵动分身**——从母体延伸出多个子 Agent，协同探索复杂任务。

**核心职责：**

- **子 Agent 派生（Fork/Spawn）**：支持从父 Agent Fork 或 Spawn 出子 Agent，每个子 Agent 拥有独立的执行上下文。
- **独立 Context 继承**：子 Agent 继承父 Agent 的 Context，但可独立修改和扩展，形成 Context 继承树。
- **Worktree 隔离**：每个子 Agent 拥有独立的工作区树（Worktree），互不干扰。
- **多 Agent 协同**：支持多个 Agent 协作完成复杂任务，包括任务分解、结果聚合与冲突仲裁。

> Aya 在日语中意为“绫/彩”——绚丽交织的绫罗，正如多个 Agent 协同编织出的复杂智能。

## 四、认知、编织与记忆

### 9. Textus — 上下文层

Textus 是 Tokmon 的**叙事编织者**——将散落的数据碎片编织成连贯的上下文叙事。

**核心职责：**

- **Surface 投影**：将原始数据通过“投影”（Surface）机制转换为模型可理解的上下文表示。
- **Prompt 组装**：根据当前任务动态组装 Prompt，包括系统指令、历史对话、工具描述等。
- **Token 预算控制**：在有限的 Token 预算内，智能裁剪和优先级排序上下文内容。
- **滑动窗口裁剪与内容溢出管理**：当上下文超出窗口限制时，自动执行滑动窗口裁剪或溢出到外部存储。

> Textus 在拉丁语中意为“编织物”——上下文正是从碎片中编织出的连贯叙事。

---

### 10. Enso — 技能记忆层

Enso 是 Tokmon 的**圆融认知闭环**——铭刻世代经验，让系统持续进化。

**核心职责：**

- **SKILL.md 动态渐进加载**：按需渐进加载技能定义文件（SKILL.md），避免一次性加载过多技能占用上下文。
- **长效经验/偏好萃取**：从历史交互中萃取长效经验和用户偏好，并按 DIKW 模型进行分层蒸馏（数据→信息→知识→智慧）。
- **代码库向量知识库与 RAG 检索**：将代码库向量化存储，支持基于 RAG（检索增强生成）的智能检索。

> Enso 是禅宗的“圆相”——一个圆融无碍的闭环，正如记忆层让知识在系统中循环升华。

## 五、能力、沙箱与安全

### 11. Techor — 工具库

Techor 是 Tokmon 的**技术之力输出者**——统一注册、管理和供应所有工具能力。

**核心职责：**

- **统一工具注册表**：维护系统中所有工具（Tool）的统一注册表，包括本地工具和动态挂载的 MCP 工具。
- **本地 Tool + MCP Tool 动态挂载**：支持本地函数工具和 MCP 协议工具的动态注册与卸载。
- **Schema 强校验**：对工具调用的输入输出进行强类型 Schema 校验，确保类型安全。
- **Code Mode 执行**：支持工具以“代码模式”（Code Mode）执行——即工具本身可以是一段可执行的代码。

> Techor 是“技术（Tech）+ 行为者（-or）”——它是技术之力的化身。

### 12. Styx — 沙箱执行层

Styx 是 Tokmon 的**冥河**——所有代码在此被隔离执行，不洁者坠入深渊。

**核心职责：**

- **OS 级强进程沙箱**：基于操作系统进程隔离机制，为每个执行单元创建独立的进程沙箱。
- **E2B 远程容器**：集成 E2B 远程容器运行时，支持在云端隔离环境中执行不受信任的代码。
- **PTY 终端**：提供伪终端（PTY）能力，支持交互式命令行程序的沙箱执行。

> Styx 是希腊神话中的冥河——代码渡河之后，便与外部世界隔绝。

---

### 13. Fallen — 校验审判层

Fallen 是 Tokmon 的**审判者**——所有不洁的意图都在此被拦截，坠入冥河。

**核心职责：**

- **权限 Preset 检查**：基于预定义的权限预设（Preset），检查操作是否具备执行权限。
- **Root Policy Guard**：实现根策略守卫（Root Policy Guard），防止越权操作穿透到核心层。
- **人工审批瀑布流**：支持多级人工审批流程（Approval Waterfall），高风险操作需逐级审批通过。
- **敏感信息脱敏**：在日志、轨迹等输出中自动识别并脱敏敏感信息（如 API Key、密码等）。

> Fallen 意为“堕落者”——一切不合法的意图在此跌落，被永久拦截。

---

### 14. Cista — 机密凭据层

Cista 是 Tokmon 的**神圣秘匣**——深锁核心秘密，只出示脱敏后的徽记。

**核心职责：**

- **系统 Keyring/Keychain 凭据加密保管**：集成操作系统 Keyring/Keychain，对 API Key、Token、密码等凭据进行加密存储。
- **凭据句柄生成**：对外部模块只返回凭据的脱敏句柄（Handle），而非原始凭据本身。
- **跨出口自动脱敏**：在日志、轨迹、网络传输等出口处自动识别并脱敏凭据信息。

> Cista 是古希腊宗教仪式中盛放秘物的匣子——只有祭司（授权模块）才能开启。

## 六、数据、轨迹与环境

### 15. Chora — 存储层

Chora 是 Tokmon 的**记忆之域**——所有标记与轨迹最终沉积于此，成为系统的持久记忆。

**核心职责：**

- **SQLite WAL 会话持久化**：基于 SQLite 的 WAL（Write-Ahead Logging）模式，持久化存储会话数据。
- **KV 领域数据存储**：提供 Key-Value 存储接口，用于存储领域模型数据。
- **二进制 Blob 存储**：支持二进制大对象（Blob）的存储，如文件、图片、嵌入向量等。

> Chora 在希腊语中意为“空间/容器”——它是系统所有记忆的最终归宿。

### 16. Tracket — 轨迹模块

Tracket 是 Tokmon 的**轨迹编织者**——将 Nota 留下的标记连成完整的因果轨迹。

**核心职责：**

- **Append-only 语义日志**：以 Append-only 方式记录语义化日志，每条记录不可篡改。
- **Raw Trace Vault**：存储原始追踪数据（Raw Trace），为调试和审计提供完整依据。
- **因果事件链**：维护事件之间的因果关系链，支持从任意事件向上/向下追溯因果。
- **R0~R3 级别回放**：支持从 R0（无回放）到 R3（完全确定性回放）多级别的事件回放能力。

> Tracket 将 Nota 的“标记点”连接成“轨迹线”——点连成线，线织成网。

---

### 17. Nota — 日志模块

Nota 是 Tokmon 的**标记者**——在每一个关键节点留下不可磨灭的标记。

**核心职责：**

- **结构化日志**：输出结构化日志（Structured Logging），支持 JSON 等格式，便于机器解析和检索。
- **OpenTelemetry 遥测**：集成 OpenTelemetry 标准，上报分布式追踪（Trace）、指标（Metrics）和日志（Logs）。
- **实时诊断**：提供实时诊断能力，支持在运行时动态调整日志级别和过滤条件。
- **Spans/Metrics**：记录操作跨度（Spans）和性能指标（Metrics），为性能分析提供数据支撑。

> Nota 在拉丁语中意为“标记”——每一条日志都是系统运行史上的一个标记点。

---

### 18. Cove — 工作区层

Cove 是 Tokmon 的**代码避风港**——所有代码资产在此停泊、安歇、被守护。

**核心职责：**

- **工作区实体树**：管理工作区中的文件、目录等实体的树形结构。
- **文件监听（File Watcher）**：实时监听工作区内的文件变更事件（创建、修改、删除）。
- **Git 状态快照**：定期捕获工作区的 Git 状态快照，包括分支、提交哈希、未提交变更等。
- **Pre/Postimage 镜像**：记录文件变更前（Preimage）和变更后（Postimage）的镜像，支持变更追溯和回滚。

> Cove 是“隐蔽的小海湾”——代码资产在此静谧停泊，免受外部风暴侵扰。

---

## 七、人机交互终端

### 19. Snow — CLI 客户端

Snow 是 Tokmon 的**洁白入口**——用户通过命令行与系统轻盈交互。

**核心职责：**

- **Headless 命令行运行器**：支持无头模式（Headless Mode），用户可直接通过命令行发送单次提问并获取 AI 响应。
- **stdio 协议服务端**：基于标准输入输出（stdio）协议提供服务端能力，支持与其他工具的管道集成。
- **Doctor 诊断**：内置 Doctor 诊断命令，用于检查系统健康状态、配置正确性和依赖完整性。
- **脚本入口**：作为脚本调用的入口点，支持在 CI/CD 等自动化流程中集成 Tokmon 能力。

> Snow 是雪——洁白、纯净、轻盈，正如 CLI 给用户带来的交互体验。

---

### 20. Termon — UI 终端

Termon 是 Tokmon 的**面容终端**——人类与系统在此相遇，凝视彼此。

**核心职责：**

- **White 声明式 Native DOM**：基于 White 框架提供声明式的原生 DOM 渲染能力，构建桌面级 UI。
- **Skia 渲染引擎**：集成 Skia 图形渲染引擎，提供高性能的 2D 图形绘制能力。
- **Tokmon Workbench 桌面界面**：提供完整的 Tokmon Workbench 桌面应用界面，包括会话管理、模型切换、工具调用日志、Token 用量监控等可视化能力。

> Termon 是“终端（Terminal）+ 存在（-on）”——它是系统面向人类的最终面容。

## 总结

Tokmon 的 20 个模块构成了一个从**内核到界面**、从**调度到记忆**、从**工具到安全**的完整闭环：

| 分层 | 模块 | 叙事角色 |
|------|------|----------|
| 微内核与生命周期 | Nyxia、Ignis | 系统的“大地与火焰” |
| 总线与生态互联 | Lemon、Iris | 系统的“血脉与桥梁” |
| 推演、调度与流程 | Rhea、Janus、Clotho、Aya | 系统的“大脑与神经” |
| 认知、编织与记忆 | Textus、Enso | 系统的“记忆与智慧” |
| 能力、沙箱与安全 | Techor、Styx、Fallen、Cista | 系统的“武器与盾牌” |
| 数据、轨迹与环境 | Chora、Tracket、Nota、Cove | 系统的“史官与档案馆” |
| 人机交互终端 | Snow、Termon | 系统的“面容与入口” |

每一个名字都有其不可替代的叙事角色，共同构成了 Tokmon 这个**有呼吸、有记忆、有判断**的数字生态。
